18  Tables for Research

Tables are fundamental to empirical research in finance. Whether you’re presenting summary statistics of your data, reporting regression results, or comparing model performance across specifications, clear and well-formatted tables communicate your findings effectively to readers. In this chapter, you’ll learn how to create publication-quality tables in Python and export them to formats suitable for academic papers.

The objectives of this chapter are to:

  1. Create descriptive statistics tables that summarize key features of your data
  2. Format regression output tables with proper presentation of coefficients, standard errors, and model statistics
  3. Export tables to LaTeX format for inclusion in academic papers
  4. Apply best practices for table design that meet journal formatting requirements

By the end of this chapter, you’ll be able to produce tables that look professional, convey information clearly, and can be easily integrated into your research papers. The emphasis is on practical workflows that save time while ensuring your tables meet the standards expected in top finance journals.

18.1 Best Practices for Research Tables

Before diving into the technical details of creating tables, it is worth reviewing some principles that will help you produce effective research tables. Cochrane (2005) offers practical advice on table design that has become standard guidance in empirical finance; here are his main points:

Self-contained captions. Each table should have a caption that allows a reader to understand its content without searching through the text. Include variable definitions and key information directly in the caption. For regression tables, state the regression equation and name the dependent variable clearly.

Discuss every number. No number should appear in a table that is not discussed somewhere in the text. You do not need to mention each number individually—“Row 1 of Table 3 shows a u-shaped pattern” is sufficient—but if a statistic is not worth writing about, it does not belong in the table.

Use appropriate precision. Report numbers with the correct number of significant digits, not whatever the computer outputs. Two to three significant digits are sufficient for most finance applications. A coefficient of 4.56783 with a standard error of 0.6789 should be reported as 4.6 with a standard error of 0.7.

Choose sensible units. Select units that make numbers easy to read. Percentages are often more intuitive than decimals. If you can report a value as 2.3 rather than 0.0000023, readers will find it easier to interpret.

18.2 Descriptive Statistics Tables

Descriptive statistics tables typically appear early in empirical papers, often labeled “Summary Statistics” or “Descriptive Statistics.” They provide readers with a quick overview of the key variables in your analysis: their central tendency, dispersion, and sometimes their distribution properties.

18.2.1 Basic summary statistics with pandas

The simplest way to generate summary statistics is using pandas’ built-in describe() method. Let’s start with a sample dataset of stock returns:

18.2.2 Customizing summary statistics

Let’s create a more informative summary statistics table tailored for financial returns:

def create_summary_stats(df):
    """
    Create customized summary statistics for financial returns.

    Parameters
    ----------
    df : pd.DataFrame
        DataFrame containing return data

    Returns
    -------
    pd.DataFrame
        Summary statistics table
    """
    stats = pd.DataFrame({
        'Mean': df.mean(),
        'Std Dev': df.std(),
        'Min': df.min(),
        'Max': df.max(),
        'Skewness': df.skew(),
        'Kurtosis': df.kurtosis(),
        'Obs': df.count()
    })

    return stats

summary_stats = create_summary_stats(df)

18.2.3 Formatting numbers for presentation

Raw statistics often have too many decimal places for presentation. Let’s format the table appropriately:

def format_summary_stats(stats_df):
    """
    Format summary statistics for presentation.

    Parameters
    ----------
    stats_df : pd.DataFrame
        Summary statistics DataFrame

    Returns
    -------
    pd.DataFrame
        Formatted summary statistics
    """
    # Create a copy to avoid modifying original
    formatted = stats_df.copy()

    # Format each column appropriately
    for col in ['Mean', 'Std Dev', 'Skewness', 'Kurtosis']:
        formatted[col] = formatted[col].apply(lambda x: f"{x:.4f}")

    for col in ['Min', 'Max']:
        formatted[col] = formatted[col].apply(lambda x: f"{x:.3f}")

    # Keep Obs as integer
    formatted['Obs'] = formatted['Obs'].astype(int)

    return formatted

formatted_stats = format_summary_stats(summary_stats)

Different statistics require different precision levels:

  • Returns and prices: 2-3 decimal places typically suffice
  • Statistical tests (t-stats, p-values): 2-3 decimal places
  • R-squared values: 2-3 decimal places
  • Sample sizes: No decimal places (integers)

When in doubt, check recent papers in your target journal to see their conventions.

18.2.4 Panel data summary statistics

When working with panel data (multiple entities observed over time), you often want to present both cross-sectional and time-series dimensions. Panel datasets contain variation across firms and over time, and summary statistics should help readers understand both sources of variation. A common approach is to compute time-series averages for each firm and then report statistics on the distribution of these averages across firms. Similarly, you can compute cross-sectional averages for each time period and examine their time-series properties.

# Create panel data: returns for 10 firms over 60 months
np.random.seed(123)

18.2.5 Comparing groups in summary statistics

Research papers often compare statistics across different groups, such as treated versus control units or large versus small firms. These comparison tables help readers quickly assess whether observable characteristics differ systematically between groups. In treatment effect studies, balance tables show whether treatment and control groups are similar on key covariates. In asset pricing, portfolio sorts compare characteristics across firms sorted by variables like size or value.

# Add a grouping variable based on median market cap
median_cap = panel_df['market_cap'].median()
panel_df['size_group'] = np.where(panel_df['market_cap'] >= median_cap, 'Large', 'Small')

# Reshape data to long format for easier grouping
long_df = panel_df.melt(
    id_vars=['firm_id', 'period', 'size_group'],
    value_vars=['returns', 'book_to_market'],
    var_name='Variable',
    value_name='Value'
)

# Group by variable first, then by size
grouped_stats = long_df.groupby(['Variable', 'size_group'])['Value'].agg(['mean', 'std', 'count'])
grouped_stats.columns = ['Mean', 'Std Dev', 'N']
grouped_stats.index = grouped_stats.index.set_levels(
    [['Book-to-Market', 'Returns'], ['Large', 'Small']],
    level=[0, 1]
)
grouped_stats.index = grouped_stats.index.set_names(['Variable', 'Size Group'])
grouped_stats = grouped_stats.sort_index()

18.2.6 Adding statistical tests to summary tables

When comparing groups, you often want to test whether differences are statistically significant. Including formal hypothesis tests alongside summary statistics strengthens your analysis by quantifying the uncertainty around observed differences. A common approach is to report the difference in means along with a t-statistic and p-value, allowing readers to assess both the magnitude and statistical reliability of the difference.

from scipy import stats as scipy_stats

def add_difference_test(df, group_col, value_cols):
    groups = df[group_col].unique()
    if len(groups) != 2:
        raise ValueError("Grouping variable must have exactly 2 groups")

    results = []

    for col in value_cols:
        group1_data = df[df[group_col] == groups[0]][col].dropna()
        group2_data = df[df[group_col] == groups[1]][col].dropna()

        mean1 = group1_data.mean()
        mean2 = group2_data.mean()

        # Two-sample t-test
        t_stat, p_value = scipy_stats.ttest_ind(group1_data, group2_data)

        results.append({
            'Variable': col,
            f'{groups[0]} Mean': f'{mean1:.4f}',
            f'{groups[1]} Mean': f'{mean2:.4f}',
            'Difference': f'{mean1 - mean2:.4f}',
            't-stat': f'{t_stat:.3f}',
            'p-value': f'{p_value:.3f}'
        })

    return pd.DataFrame(results)

# Test differences between small and large firms
diff_test = add_difference_test(panel_df, 'size_group', ['returns', 'book_to_market'])

The appropriate test for your analysis depends on the properties of your data, including sample size, distribution shape, and whether observations are independent or paired. Consult a statistics textbook or your methodology course notes when choosing among alternative hypothesis tests.

18.3 Regression Output Tables

Regression tables are the centerpiece of most empirical finance papers. A well-formatted regression table clearly presents coefficients, standard errors (or t-statistics), significance indicators, and model fit statistics in a compact format that allows readers to quickly assess your findings. We will cover regression methods in detail later in this book, so this section focuses on the mechanics of table creation rather than estimation.

Most researchers write custom code to generate regression tables that match their preferred format and the requirements of their target journal. This approach provides maximum control over layout, decimal precision, variable labels, and the inclusion of model diagnostics. The stargazer package (a Python port of the popular R package) offers a convenient alternative for quickly generating publication-quality tables with standard formatting conventions; we use it below, once we get to LaTeX output.

TipSignificance stars

The convention for significance stars in finance research is:

  • *** : p < 0.01 (1% level)
  • ** : p < 0.05 (5% level)
  • * : p < 0.10 (10% level)

Always include a note below your table explaining this convention. Some journals discourage stars and prefer reporting exact p-values or confidence intervals instead.

18.3.1 Estimating the models

To make this concrete, we estimate two market-model regressions on the monthly returns created at the start of the chapter. Each regression relates one stock’s return to the return on an equal-weighted portfolio of the five stocks, which stands in for the market:

\[r_{i,t} = \alpha_i + \beta_i r_{m,t} + \varepsilon_{i,t}\]

import statsmodels.api as sm

market = df.mean(axis=1)
X = sm.add_constant(market.rename('Market'))

capm_aapl = sm.OLS(df['AAPL'], X).fit()
capm_msft = sm.OLS(df['MSFT'], X).fit()

print(capm_aapl.summary().tables[1])

18.3.2 Writing your own regression table

The statsmodels summary output is convenient for checking your work, but it is far too verbose for a paper. The function below extracts what a journal table needs—coefficients, standard errors in parentheses, significance stars, and a few model statistics—and assembles it into a DataFrame with one column per specification:

def significance_stars(p_value):
    """Return significance stars following the finance convention."""
    if p_value < 0.01:
        return '***'
    elif p_value < 0.05:
        return '**'
    elif p_value < 0.10:
        return '*'
    return ''

def regression_table(results, model_names, labels):
    """
    Assemble fitted regression results into a presentation table.

    Parameters
    ----------
    results : list of statsmodels results objects
        One fitted model per column of the table
    model_names : list of str
        Column headers, typically the dependent variable
    labels : dict
        Maps variable names to the labels shown in the table

    Returns
    -------
    pd.DataFrame
        Formatted regression table
    """
    columns = {}
    for res, name in zip(results, model_names):
        entries = []
        for var in labels:
            stars = significance_stars(res.pvalues[var])
            entries.append(f"{res.params[var]:.3f}{stars}")
            entries.append(f"({res.bse[var]:.3f})")
        entries.extend([f"{int(res.nobs)}", f"{res.rsquared:.3f}"])
        columns[name] = entries

    index = []
    for label in labels.values():
        index.extend([label, ''])
    index.extend(['Observations', 'R-squared'])

    return pd.DataFrame(columns, index=index)

reg_table = regression_table(
    [capm_aapl, capm_msft],
    model_names=['AAPL', 'MSFT'],
    labels={'Market': 'Market beta', 'const': 'Alpha'},
)
reg_table

18.4 Introduction to LaTeX Tables

Most finance journals accept PDF or Word files at submission, but many authors write their papers in LaTeX, and journals such as the Journal of Finance and the Journal of Financial Economics typically ask for LaTeX source files once a paper is accepted. If you write in LaTeX, converting your Python tables to LaTeX automatically saves a great deal of tedious copying and eliminates a common source of errors.

18.4.1 Understanding LaTeX table structure

A basic LaTeX table has this structure:

\begin{table}[htbp]
  \centering
  \caption{Summary Statistics}
  \label{tab:summary}
  \begin{tabular}{lcccc}
    \toprule
    Variable & Mean & Std Dev & Min & Max \\
    \midrule
    Returns & 0.0105 & 0.0543 & -0.1234 & 0.1876 \\
    Market Cap & 12.45 & 2.34 & 8.12 & 18.99 \\
    \bottomrule
  \end{tabular}
  \begin{tablenotes}
    \small
    \item Note: All values are in decimals.
  \end{tablenotes}
\end{table}

Key components:

  • \begin{table}...\end{table}: Table environment
  • \caption{}: Table title
  • \label{}: Reference label for citing in text
  • \begin{tabular}...\end{tabular}: The actual table
  • {lcccc}: Column alignments (l=left, c=center, r=right)
  • \toprule, \midrule, \bottomrule: Professional-looking horizontal lines
  • \begin{tablenotes}...\end{tablenotes}: Notes below table

18.4.2 Converting pandas DataFrames to LaTeX

pandas provides built-in LaTeX export functionality:

TipLaTeX table best practices

Follow these conventions for professional tables:

  1. Use booktabs package: Provides \toprule, \midrule, \bottomrule for clean horizontal lines
  2. Avoid vertical lines: Modern table design omits vertical separators
  3. Align numbers properly: Center or right-align numeric columns, left-align text
  4. Add informative notes: Explain variable definitions, sample restrictions, significance levels
  5. Use consistent precision: Don’t mix 2 and 4 decimal places randomly
  6. Include label: Always add \label{} so you can reference tables in text with \ref{}

18.4.3 Exporting regression tables with stargazer

to_latex() works well for tables you have already formatted yourself, but regression tables have enough recurring structure—stacked standard errors, significance stars, a block of model statistics, a note at the bottom—that it is worth letting a package handle it. stargazer takes a list of fitted statsmodels results and produces either HTML or LaTeX:

from stargazer.stargazer import Stargazer

star_table = Stargazer([capm_aapl, capm_msft])
star_table.title('Market Model Regressions')
star_table.custom_columns(['AAPL', 'MSFT'], [1, 1])
star_table.covariate_order(['Market', 'const'])
star_table.rename_covariates({'Market': 'Market beta', 'const': 'Alpha'})
star_table.significant_digits(3)

print(star_table.render_latex())

WarningCheck the output before you submit

stargazer writes plain LaTeX that assumes nothing beyond the standard table and tabular environments, so it does not use booktabs rules and its layout will not match every journal’s template. Treat its output as a starting point: compile it, look at it, and edit the generated code (or fall back to your own table function) when the journal asks for something different.

18.4.4 Saving tables to files

In practice, you’ll want to save your LaTeX tables to files for inclusion in your paper. Writing the LaTeX string to a .tex file takes a single call, and pathlib makes it easy to create the output directory if it does not exist yet:

import tempfile
from pathlib import Path

output_dir = Path(tempfile.mkdtemp()) / 'tables'
output_dir.mkdir(parents=True, exist_ok=True)

(output_dir / 'summary_stats.tex').write_text(latex_output)
(output_dir / 'market_model.tex').write_text(star_table.render_latex())

sorted(path.name for path in output_dir.iterdir())

You then pull each table into your paper with \input{tables/market_model.tex}, and the numbers in your document update automatically the next time you re-run the script.

NoteWorkflow for managing tables

A recommended workflow for research papers:

  1. Generate all tables in Python: Keep table generation code in well-organized scripts
  2. Export to .tex files: Save each table to a separate file in a tables/ directory
  3. Include in main document: Use \input{} to include tables in your paper
  4. Automate updates: When data or specifications change, re-run Python scripts to update all tables

This separation keeps your main LaTeX document clean and makes it easy to update tables as your research evolves.
